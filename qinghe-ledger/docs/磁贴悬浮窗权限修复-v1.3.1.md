# 磁贴悬浮窗误判修复 · v1.3.1

> 症状：小米 HyperOS 已在系统设置允许「悬浮窗 / 显示在其他应用上层」，点状态栏
> 「记账识别」磁贴仍持续提示「请先允许悬浮窗，识别结果才能弹卡」，无法进入识别。
>
> 结论：不是 OCR、截图或确认卡的问题，是**悬浮窗权限判断发生在 TileService 的 Context**，
> 且透明授权页 `CapturePermissionActivity` 又重复判断一次，形成“授权了也一直提示”的循环。

---

## 1. 本次 bug 的根因

### 根因一：TileService 的 Context 判断悬浮窗不可靠

`RecognitionTileService.onClick()` 原来的逻辑：

```java
if (!TileStore.canOverlay(this)) {
    toast("请先允许悬浮窗，识别结果才能弹卡");
    // 跳系统设置
    return;
}
```

`TileService` 由系统 SystemUI 启动，虽然 `this` 是 App 的 Service，但部分 HyperOS /
MIUI 版本在快捷设置服务的 Context 里调用 `Settings.canDrawOverlays()` 会返回 `false`，
即使系统设置页对该包名已经显示“允许”。这是 OEM 的权限回读差异，不是用户没授权。

### 根因二：透明页又判断一次，导致无法自愈

`CapturePermissionActivity.onCreate()` 里还有同样的判断：

```java
if (!TileStore.canOverlay(this)) {
    Toast.makeText(this, "请先允许悬浮窗，识别结果才能弹卡确认", ...).show();
    // 跳系统设置
    finish();
    return;
}
```

所以即使磁贴那次判断碰巧通过，只要透明页的 Context 仍然回读为 false，用户就会再次被弹回
系统设置；返回后再点，仍然重复。用户感知就是“权限明明开了，但一直让我开权限”。

### 根因三：检查对象确认

代码检查的是 `Settings.canDrawOverlays(context)`，底层对应
`android.permission.SYSTEM_ALERT_WINDOW` / AppOps `OPSTR_SYSTEM_ALERT_WINDOW`，**不是**
通知权限、不是屏幕捕获权限、也不是“后台弹出界面”。这部分本身没有检查错权限；
错的是**在哪个 Context 检查**，以及**重复检查**。

### 修复原则

- 磁贴只负责把“用户点了磁贴”这件事带回主 Activity；
- 悬浮窗权限只在 `MainActivity` 的 Activity Context 中判断一次；
- 已授权：直接继续截图识别，不再显示任何悬浮窗提示；
- 未授权：跳系统悬浮窗页，并提示 HyperOS 用户“强杀 App 后重开”；
- 删除透明页和 Service 里的重复判断，避免二次误判；
- 不改 OCR、不改磁贴本身、不改 `RecognitionOverlay` 确认卡组件。

> 另一个必须处理的细节：`MainActivity` 不能停留在前台，否则截图会截到记账 App 自己。
> 因此主 Activity 校验通过后，立即启动透明的 `CapturePermissionActivity` 并 `finish()` 自己，
> 让透明页直接盖在支付成功页上，MediaProjection 才能截到下方支付页。

### 3.2 MainActivity.java

新增常量、状态和方法：

```java
private static final String TAG = "QHTile";
private boolean tileTriggerPending = false;
private boolean overlayDialogShown = false;
private boolean overlayRetryToastShown = false;

@Override
protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    ...
    setContentView(root);
    consumeTileTrigger(getIntent());
    ...
}

@Override
protected void onResume() {
    super.onResume();
    RecognitionTileService.requestUpdate(this);
    ui.postDelayed(new Runnable() {
        @Override public void run() { deliverPendingRecognition(); }
    }, 300);
    // 从磁贴/悬浮窗设置返回后，重新校验并继续识别
    ui.postDelayed(new Runnable() {
        @Override public void run() { maybeStartTileRecognition(); }
    }, 380);
}

@Override
protected void onNewIntent(Intent intent) {
    super.onNewIntent(intent);
    setIntent(intent);
    if (intent != null) {
        String data = intent.getStringExtra("recognition");
        if (data != null) {
            deliverRecognition(data, intent.getBooleanExtra("auto_commit", false));
        }
    }
    consumeTileTrigger(intent);
    ui.postDelayed(new Runnable() {
        @Override public void run() { maybeStartTileRecognition(); }
    }, 200);
}

/** 磁贴点击只传一个动作标记，权限校验和后续链路都在 Activity 里完成。 */
private void consumeTileTrigger(Intent intent) {
    if (intent == null) return;
    boolean trigger = RecognitionTileService.ACTION_TILE_RECOGNIZE.equals(intent.getAction())
            || intent.getBooleanExtra("tile_recognize", false);
    if (!trigger) return;
    tileTriggerPending = true;
    overlayDialogShown = false;
    overlayRetryToastShown = false;
    intent.setAction(null);
    intent.removeExtra("tile_recognize");
    setIntent(intent);
    Log.i(TAG, "tile trigger received in MainActivity");
}

private void maybeStartTileRecognition() {
    if (!tileTriggerPending || isFinishing() || webView == null) return;

    // 只检查 SYSTEM_ALERT_WINDOW；必须在 Activity 的 Context 中执行
    boolean granted = TileStore.canOverlay(this);
    Log.i(TAG, "overlay check in MainActivity: granted=" + granted
            + ", " + TileStore.overlayDebug(this));
    if (!granted) {
        if (!overlayDialogShown) {
            overlayDialogShown = true;
            showOverlayPermissionDialog();
        } else if (!overlayRetryToastShown) {
            overlayRetryToastShown = true;
            Toast.makeText(this,
                    "仍未检测到悬浮窗权限。小米 HyperOS 请完全杀掉 App 进程后重新打开再试",
                    Toast.LENGTH_LONG).show();
        }
        return;
    }

    tileTriggerPending = false;
    Log.i(TAG, "overlay granted, continue screen capture");
    try {
        // 先由 MainActivity 校验权限，再交给透明授权页，并立即 finish 自己，
        // 这样透明页背后仍是支付成功页，截图不会截到辣脚记账自己的界面。
        startActivity(new Intent(this, CapturePermissionActivity.class));
        finish();
    } catch (Exception e) {
        Log.e(TAG, "start CapturePermissionActivity failed", e);
        Toast.makeText(this, "无法启动屏幕识别，请重试", Toast.LENGTH_SHORT).show();
    }
}

private void showOverlayPermissionDialog() {
    try {
        new AlertDialog.Builder(this)
                .setTitle("需要悬浮窗权限")
                .setMessage("请允许「悬浮窗 / 显示在其他应用上层」，识别结果才能弹卡确认。\n\n"
                        + "小米 HyperOS 如果系统里已经开启、这里仍然提示，请完全杀掉辣脚记账的进程，"
                        + "重新打开 App 后再点磁贴。")
                .setPositiveButton("去授权", new DialogInterface.OnClickListener() {
                    @Override public void onClick(DialogInterface dialog, int which) {
                        openOverlaySettings();
                    }
                })
                .setNegativeButton("稍后", null)
                .show();
    } catch (Exception e) {
        Log.e(TAG, "show overlay dialog failed", e);
        openOverlaySettings();
    }
}

private void openOverlaySettings() {
    try {
        Intent i = new Intent(Settings.ACTION_MANAGE_OVERLAY_PERMISSION,
                Uri.parse("package:" + getPackageName()));
        startActivity(i);
    } catch (Exception e) {
        Log.e(TAG, "open overlay settings failed", e);
        try {
            startActivity(new Intent(Settings.ACTION_MANAGE_OVERLAY_PERMISSION));
        } catch (Exception ignored) { }
    }
}
```

```diff
+    /** 只检查系统悬浮窗权限（SYSTEM_ALERT_WINDOW / AppOps），不检查通知等其他权限。 */
     public static boolean canOverlay(Context context) {
         return Settings.canDrawOverlays(context);
     }
+
+    /** 给调试日志用的原始结果：canDrawOverlays 与 AppOps 的实际 mode。 */
+    public static String overlayDebug(Context context) {
+        int mode = -999;
+        try {
+            AppOpsManager ops = (AppOpsManager) context.getSystemService(Context.APP_OPS_SERVICE);
+            if (ops != null) {
+                mode = ops.checkOpNoThrow(AppOpsManager.OPSTR_SYSTEM_ALERT_WINDOW,
+                        context.getApplicationInfo().uid, context.getPackageName());
+            }
+        } catch (Exception ignored) { }
+        return "canDrawOverlays=" + Settings.canDrawOverlays(context)
+                + ", appOps=" + mode
+                + ", sdk=" + Build.VERSION.SDK_INT
+                + ", pkg=" + context.getPackageName();
+    }
```

## 4. 2 条测试验证步骤

### 测试 1：已授权时不再提示，直接进入识别

1. 在 HyperOS 设置中给辣脚记账开启「悬浮窗 / 显示在其他应用上层」。
2. 完全杀掉辣脚记账进程，重新打开一次，再回到桌面。
3. 在微信/支付宝的支付成功页，下拉状态栏点「记账识别」。
4. 预期：不再出现「请先允许悬浮窗」的提示；出现系统屏幕捕获授权（或直接识别），
   随后弹出金额/商户确认卡。
5. 用 `adb logcat -s QHTile` 查看：
   `overlay check in MainActivity: granted=true, canDrawOverlays=true, appOps=0 ...`
   以及 `overlay granted, continue screen capture`。

### 测试 2：未授权时跳设置，授权返回后自动继续

1. 在系统设置中关闭辣脚记账的悬浮窗权限。
2. 点磁贴。
3. 预期：App 打开并显示「需要悬浮窗权限」对话框；点「去授权」进入系统悬浮窗页。
4. 开启权限后按返回键回到 App。
5. 预期：自动继续截图识别流程，不再要求第二次授权；`adb logcat -s QHTile` 中
   第二次输出 `granted=true`。
6. HyperOS 若已开启仍报错：按对话框提示完全杀掉 App 进程，重新打开后点磁贴再试；
   日志里对比 `canDrawOverlays` 与 `appOps` 哪一项仍为 false，可快速定位是系统未生效还是判断上下文问题。
