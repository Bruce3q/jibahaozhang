# 相册截图识别（v1.4.0）

> 目标：彻底移除无障碍与 MediaProjection。用户自己截屏，App 只读取这张截图并本地 OCR，
> 识别结果弹卡确认后才入账。

## 1. 根因与取舍

- Android 没有公开的“触发系统截图”Intent。v1.3.3 使用 `AccessibilityService#takeScreenshot()`
  是唯一能直接拿 Bitmap 的公开入口，因此“系统截图模式”始终需要一个无障碍服务。
- 这与“确保所有无障碍功能都被删除”冲突，也不符合用户对权限的预期。
- v1.4.0 改为 **相册截图**：用户在支付成功页按“音量下 + 电源”截屏，再点状态栏磁贴；
  App 读取最近 3 分钟的截图，走原有 Tesseract OCR / 支付页解析 / 确认卡。
- 结果：`AndroidManifest.xml` 中不再有 `BIND_ACCESSIBILITY_SERVICE`、`AccessibilityService`、
  `MediaProjection` 或录屏前台服务。

## 3. 使用步骤

1. 在微信 / 支付宝 / 云闪付的支付成功页，按 **音量下 + 电源** 截屏；
2. 下拉状态栏，点「记账识别」磁贴；
3. 首次会请求“读取照片”，Android 13+ 请选 **允许所有照片**；再允许悬浮窗；
4. App 读取刚拍的截图，本地 OCR 后弹出确认卡；
5. 核对金额、商户、分类、备注，点「确认入账」才写入。

## 4. 验证与限制

- 网页端经 mock 验证：识别弹窗四步、无“无障碍/系统截图/旧方案”文案；`node --check` 通过。
- APK 构建通过；`aapt2 dump xmltree` 确认只有 `TileTriggerActivity`、`GalleryOcrService`，
  无任何 `AccessibilityService` 声明；`dexdump` 无 `Accessibility`/`ScreenOcrService` 类。
- 版本：v1.4.0 / versionCode 12；APK 约 14 MB（含 Tesseract 中文模型与四 ABI 原生库）。
- 未做真机测试；相册权限、厂商截图命名、悬浮窗行为需在目标机型实机验证。
- 必须先截屏再点磁贴；App 不主动截屏、不监听截图事件、不读取其他照片。
