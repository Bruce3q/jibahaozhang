# 状态栏磁贴：一次点击完成系统截图（v1.3.4）

## 1. 根因判断

这次不是 OCR 或截图慢，而是**触发链路把 App 拉到了前台**。

旧链路：

```text
点磁贴
  → RecognitionTileService 启动 MainActivity
  → MainActivity 校验悬浮窗
  → ScreenshotAccessibilityService.captureAfterAppExit()
  → MainActivity.finish()
```

问题有三层：

1. **MainActivity 一旦启动，微信支付页就被盖住**。虽然它马上 `finish()`，但用户看到的是辣脚记账页面，必须手动切回微信；切回后再点磁贴，等于第二次触发。
2. **`busy` 是单次状态**。第一次触发后如果截图/OCR/悬浮卡任意一步没有走到 `finishRound()`，`busy` 会一直为 true；第二次点击被 `if (s.busy) return` 直接吞掉，于是“无响应”。
3. **权限提示被混在一起**。旧代码在 MainActivity 里用“无障碍”笼统描述，用户无法区分“读取屏幕文字”和“系统截图辅助”。

### 关于“系统截图不需要无障碍权限”的技术说明

Android **没有公开的“触发系统截图”Intent**。第三方 App 要拿到“当前屏幕的原生像素、不经过 MediaProjection”，唯一公开入口是：

```java
AccessibilityService.takeScreenshot(...)   // Android 11+
```

因此：

- 系统截图模式**不需要**旧版“读取屏幕文字”的无障碍服务；
- 但它**必须**开启一个只声明 `canTakeScreenshot=true`、`canRetrieveWindowContent=false` 的“系统截图辅助”服务。这个服务在系统设置里仍然归在“无障碍”分类下，这是 Android 的归类方式，不是我们在读取屏幕内容；
- 如果完全关闭所有无障碍服务，系统截图模式无法工作；此时只能退回 MediaProjection 旧方案（不需要无障碍，但小米会触发共享防护模糊）。

这一条无法用代码绕过，除非使用 Shizuku/ADB 或系统签名权限，均不适合普通安装包。本次按“模式分层”修正提示：系统截图模式只提示「系统截图辅助」，不再提示笼统的“无障碍功能”。

### 3.1 磁贴改为透明页

### 3.2 透明 Activity：校验后立刻退场

```java
public class TileTriggerActivity extends Activity {
    @Override protected void onCreate(Bundle b) {
        super.onCreate(b);                 // 不 setContentView，主题透明
        if (!TileStore.isEnabled(this)) { finish(); return; }
        checkAndProceed();
    }

    private void checkAndProceed() {
        String mode = TileStore.captureMode(this);
        Log.i(TAG, "mode=" + mode
                + " overlay=" + TileStore.canOverlay(this)
                + " screenshotEnabled=" + ScreenshotAccessibilityService.isEnabled(this)
                + " screenshotConnected=" + ScreenshotAccessibilityService.isConnected());
        if (!TileStore.canOverlay(this)) { showOverlayDialog(); return; }
        proceed();
    }

    private void proceed() {
        boolean force = getIntent().getBooleanExtra("force_projection", false);
        String mode = force ? TileStore.MODE_PROJECTION : TileStore.captureMode(this);
        if (TileStore.MODE_NATIVE.equals(mode)) {
            if (ScreenshotAccessibilityService.isConnected()) startNativeAndFinish();
            else if (ScreenshotAccessibilityService.isEnabled(this)) waitForService();
            else showServiceDialog();
            return;
        }
        startActivity(new Intent(this, CapturePermissionActivity.class));
        finish();
    }

    private void startNativeAndFinish() {
        ScreenshotAccessibilityService.captureAfterAppExit();
        finish();                          // 微信页始终在最上面
    }
}
```

### 3.3 每次点击复位状态并作废旧回调

```java
private volatile int captureToken = 0;

private void beginCapture(long delayMs) {
    final int my = ++captureToken;
    busy = false;
    if (overlay != null) { overlay.dismiss(); overlay = null; }
    main.postDelayed(new Runnable() {
        @Override public void run() {
            if (my != captureToken) return;
            busy = true;
            takeNativeShot(my);
        }
    }, delayMs);
}

public static void captureAfterAppExit() {
    ScreenshotAccessibilityService s = ref == null ? null : ref.get();
    if (s == null) return;
    s.beginCapture(700);
}
```

```java
private void takeNativeShot(final int my) {
    if (my != captureToken) return;
    takeScreenshot(Display.DEFAULT_DISPLAY, getMainExecutor(),
        new TakeScreenshotCallback() {
            @Override public void onSuccess(ScreenshotResult r) {
                if (my != captureToken) { r.getHardwareBuffer().close(); return; }
                ...
                process(copy, started, my);
            }
            @Override public void onFailure(int code) {
                if (my != captureToken) return;
                ...
            }
        });
}
```

`process()`、`showResult()`、`fail()` 都带 `my`，任何旧轮次迟到的结果直接丢弃；`finishRound()` 会 `captureToken++`，所以下一次点击一定能重新开始。

### 3.4 透明页被拦截时的通知倒计时

```java
public static void startCountdownCapture(Context context) {
    ScreenshotAccessibilityService s = ref == null ? null : ref.get();
    if (s == null) return;
    final int my = ++s.captureToken;
    s.busy = false;
    s.showCountdownNotice(context, my);    // 通知「3 秒后自动截图」
    s.main.postDelayed(new Runnable() {
        @Override public void run() {
            if (my != s.captureToken) return;
            s.beginCapture(0);             // 3 秒后自动截当前支付页
        }
    }, 3000);
}
```

### 3.5 权限按模式分层

```java
// 系统截图：只校验悬浮窗 + 系统截图辅助（takeScreenshot 的宿主）

        else showServiceDialog();          // 文案只说「系统截图辅助」，不再说“无障碍功能”
```

## 4. 验证步骤

### ① 一次点击、不跳回 App

前置：系统设置 → 无障碍 → 开启「辣脚记账 · 系统截图」（只开启这一个，旧的屏幕读取服务不要开）。

1. 微信停在支付成功页。
2. 下拉状态栏，点「记账识别」。
3. 预期：**不出现辣脚记账主页**，最多一瞬间透明页；700ms 后截图，弹出确认卡。
4. 日志确认：

```bash
adb logcat -s QHTileTrigger QHNativeShot
# transparent trigger created
# mode=native overlay=true screenshotEnabled=true screenshotConnected=true
# native screenshot ok
```

### ② 连续点击不锁死

1. 第一次弹卡后点「忽略」。
2. 立刻再点磁贴，重复 3 次。
3. 每次都应重新截图、重新弹卡；如果上一次仍在识别，新一次会作废旧 token，不允许出现“点了没反应”。

```bash
adb logcat -s QHTileTrigger QHNativeShot | grep -E "transparent trigger|native screenshot start|captureToken"
```

### ③ 失败文案

1. 把微信停在一个没有“支付成功”的页面，点磁贴。
2. 预期提示“识别到画面，但未找到支付信息”或“请停留在支付成功页面”，**不再出现**“系统截图服务正在启动，请回到支付页再点一次磁贴”。

### ④ 权限提示（重要）

- 关闭所有无障碍后，native 模式**无法截图**，这是 Android API 限制；此时应提示「需要系统截图辅助」，不再显示笼统的“请开启无障碍功能”。
- 如果坚持完全不用无障碍：切到「旧方案」，它只校验悬浮窗和 MediaProjection 授权；小米会先显示「屏幕共享防护」提示，画面可能模糊。

### ⑤ 自动删图

识别后检查 `Pictures/辣脚记账`，默认不留图；关闭设置里的开关后才保留，便于调试。
