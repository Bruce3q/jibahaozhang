# 辣脚记账 v1.6.0 · 支付页快速记账（悬浮球 / 识别截图 / 通知栏 / 桌面小组件）

> 适用版本：**v1.6.0（versionCode 16）** · 产物 `dist/辣脚记账-1.6.0.apk`
> 目标：在微信/支付宝的支付页旁边，用最短路径记一笔，不再依赖「通知监听」「无障碍」「磁贴截图」这三套自动化。

---

## 一、为什么换成手动入口（方案对比）

前面三套自动化都试过，结论很直接：

| 方案 | 支付页可用性 | 需要权限 | 实测结论 |
| --- | --- | --- | --- |
| 无障碍取词 | 好 | 无障碍（极敏感） | 系统/厂商会自行关闭服务，用户不接受 |
| 状态栏磁贴 + 截图 | 中 | 悬浮窗 + 截图 | 要先下拉磁贴、再回支付页，流程反人类 |
| 相册截图 OCR | 中 | 相册 | 悬浮窗误报、识别超时，链路太长 |
| 通知监听自动记账 | 依赖通知文案 | 通知使用权 | 微信通知文案多变，实测抓不到 |
| **悬浮球 + 记账小窗（本版主推）** | **好** | 悬浮窗 | 支付页点一下小球就地记账，最可靠 |
| **小窗「识别截图」** | **好** | 相册 | 截图后本地 OCR 预填金额/商户，省打字 |
| **通知栏常驻「记一笔」** | 好 | 通知 | 不需要悬浮窗权限的兜底入口 |
| **桌面小组件** | 弱（要先回桌面） | 无 | 早餐 ¥10 / 午餐 ¥20 一秒入账 |

一句话：**手动入口 > 全自动猜测**。自动识别只作为「预填」，最终入账永远由用户点「保存/确认」。

## 二、四个入口怎么用

### 1. 悬浮球（推荐）
1. 「我的 → 快速记账 → 悬浮球快捷记账」→ 打开开关；
2. 按提示「允许悬浮窗」（系统设置 → 应用 → 辣脚记账 → 显示在其他应用上层）；
3. 支付页出现绿色小圆球「记」，**点一下**弹出记账小窗：
   - 11 个分类胶囊（含三餐、洗澡、饮水、收入）；
   - 数字键盘 + 金额；
   - 「识别截图」按钮（可选）；
   - 「保存」→ 账单进入本地队列，App 下次打开（或已在后台时立即）自动入账；
4. 小球可**长按拖动**到顺手的位置（位置会被记住）；
5. 「我的 → 快速记账 → 悬浮球」里可随时关掉。

### 2. 小窗「识别截图」（省打字）
1. 先在支付成功页按 **音量下 + 电源** 截屏（微信/支付宝均可）；
2. 点悬浮球 → 点小窗里的「识别截图」；
3. 首次会申请**相册权限**（只读最新截图，本地 OCR，不上传、不联网）；
4. 识别到的金额与商户**填进小窗**，确认无误再点「保存」；
5. 识别不到会提示「请手动输入」，不会瞎记账。

### 3. 通知栏常驻「记一笔」
1. 「我的 → 快速记账 → 通知栏常驻」→ 打开开关；
2. 下拉状态栏能看到「辣脚记账 · 快捷记账」，直接点：
   - 「记一笔」→ 打开 App 记账面板；
   - 「早餐 ¥10」「午餐 ¥20」→ **不打开 App**，直接入队，通知栏提示「已记 ¥10 早餐」；
3. 不需要悬浮窗权限，适合不习惯悬浮球的场景。

### 4. 桌面小组件
1. 「我的 → 快速记账 → 桌面小组件」→「请求添加到桌面」（或长按桌面 → 小组件 → 辣脚记账）；
2. 三个按钮：**早餐 ¥10 / 午餐 ¥20 / 记一笔**；
3. 前两个点一下直接入队并刷新组件文案，第三个打开 App 面板。

> 入队 = 先写在本机 `SharedPreferences`，回到 App 后由页面 `QHApp.commitQuick()` 真正写进账本，**重复提交会按「金额+分类+日期+备注」去重**。

### 再次打包的 OCR（只保留 arm64）
- `android-build/ocr/tesseract4android.aar` → 取 `classes.jar` + `jni/arm64-v8a/*.so`；
- 模型 `chi_sim.traineddata` 放进 `assets/tessdata/`；
- 同时写入**两套 `.so` 名字**（`libtesseract.so` 与 `libtess.so`、`libleptonica.so` 与 `liblept.so`、`libjpeg.so` 与 `libjpgt.so`、`libpngx.so` 与 `libpngt.so`），覆盖两种 `loadLibrary` 命名，避免再次出现 `TessBaseAPI` 类加载失败。

## 四、实现链路（一张图）

```
悬浮球小窗「保存」 ┐
通知栏「早餐 ¥10」 ├─→ QuickStore.enqueue()  →  SharedPreferences 队列
桌面小组件按钮   ┘                                   │
                                                     ▼
                            MainActivity.pushQuickToApp()（进程在就立即投递）
                                                     │
                    页面就绪？ pageReady ── 否 ──→ 保留队列，回到 App 再投
                                                     │ 是
                            JS: window.QHApp.commitQuick(json)
                                                     │
                            Store.addTransactions() → 去重 → 写账本 → render() 刷新全部页面
                                                     │
                            返回 true → 原生 QuickStore.popFirst() 出队
                            返回 false → 700ms 后重试，最多 3 次
```

- **开关与状态**：`QHQuick` 桥（`isBallEnabled/setBallEnabled/isNotifyQuickEnabled/setNotifyQuickEnabled/overlayGranted/hasGalleryPermission/queueSize/requestPinWidget/openSettings`），前端设置页与原生 `SharedPreferences` 双向同步。
- **降级**：没有悬浮窗权限 → 打开开关时提示去授权，但仍可用通知栏入口；没有相册权限 → 识别按钮提示去授权，手动输入照常。
- **通知监听自动记账保留**：v1.5.0 的微信通知监听没有被删，作为第五个「自动」入口继续存在（默认关闭）。

## 六、边界与限制（必须知道）

1. **只在 arm64 手机上有效**：v1.6.0 的 APK 只打 arm64-v8a 的 OCR 库（体积从 27 MB 降到 17 MB）。极老的 32 位机型装得上但「识别截图」不可用，手动记账不受影响。
2. **OCR 只认中文简体**：模型是 `chi_sim`，英文/数字没问题，生僻排版可能识别不准 —— 识别结果只做预填，永远以你点的「保存」为准。
3. **相册权限只用于「识别截图」**：不点这个按钮，App 不会读相册。识别完全在本机完成，不联网、不上传。
4. **小米/HyperOS 保活**：悬浮球是前台服务，建议同时打开「自启动」、把电池策略设为「无限制」，否则锁屏久了小球可能被系统回收（重新打开 App 会自动恢复）。
5. **桌面小组件更新有延迟**：组件文案由 `AppWidgetManager` 刷新，系统可能延迟几秒。
6. **通知栏常驻入口**：Android 13+ 需要允许通知；被划掉后重新打开开关或重启 App 会恢复。

## 七、真机验证步骤（4 条）

1. **悬浮球**：设置里打开悬浮球 → 到微信聊天页（不打开辣脚记账）→ 点小球 → 选「午餐」→ 输入 23 → 保存 → 打开 App，首页日程里应看到这笔 ¥23.00 午餐。
2. **识别截图**：在支付成功页截屏 → 点小球 → 「识别截图」→ 小窗金额/商户被填上 → 保存 → 账本里金额与备注正确；再把同一张截图识别一次，不应产生第二笔（金额+分类+日期+备注去重）。
3. **通知栏**：打开通知栏常驻 → 下拉状态栏点「早餐 ¥10」→ 通知栏提示「已记 ¥10 早餐」→ 打开 App 看到该笔；关掉开关后通知消失、再点不再入账。
4. **降级路径**：在系统设置里关掉辣脚记账的悬浮窗权限 → 打开悬浮球开关 → 应提示去授权而不是崩溃；关掉相册权限 → 点「识别截图」应提示授权并允许继续手动输入。
