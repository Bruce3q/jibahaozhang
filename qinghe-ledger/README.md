# 辣脚记账

> 极简、无广告、纯本地的日常记账工具。三餐三步记完，账单按日历看，预算实时提醒。

辣脚记账是一个为手机竖屏设计的离线 Web App（PWA），不依赖任何后端、账号或第三方统计。
所有账单只写入浏览器本地存储，断网也能用；既可以作为 PWA 装到主屏幕，也可以直接用单文件
HTML 打开。当前版本 **v1.6.3**（在 v1.6.2 基础上新增：累计结余按月切换、备注搜索起止日期、洗衣分类；其余功能与交互不变）。

> v1.6.3 三项新增：见 [三项新增说明](docs/三项新增-v1.6.3.md)。

> 通知监听自动记账（可选，仍在）：见 [v1.5.0 通知监听自动记账](docs/通知监听自动记账-v1.5.0.md)。

## 一、30 秒开始使用

### 方式 A：单文件版（最省事，推荐）

直接双击打开：

```
dist/辣脚记账.html
```

所有 CSS、JS、图标都已内联，不需要服务器、不需要联网，适合发到手机里用浏览器打开，
或放进 U 盘 / 网盘随身携带。

### 方式 B：本地服务器版（可安装 PWA / 体验离线缓存）

项目自带一个零依赖的预览服务器（需要 Python 3.9+）：

```bash
cd qinghe-ledger
python serve.py
# 打开 http://127.0.0.1:5178
```

手机与电脑在同一 Wi-Fi 时：

```bash
python serve.py --lan
# 终端会打印 http://<你的局域网 IP>:5178，手机浏览器访问即可
```

在 iOS Safari 中「分享 → 添加到主屏幕」，或在 Android Chrome 中「安装应用」，
即可获得接近原生 App 的全屏体验；Service Worker 会缓存界面资源，断网也能打开。

### 方式 C：直接打开源码入口

```
index.html
```

源码版没有打包，双击也能运行（`file://` 下会自动跳过 Service Worker 注册）。

### 方式 D：Android APK

直接安装：

```
dist/辣脚记账-1.6.3.apk   （v1.6.3，157 KB，已移除 OCR、通知监听与桌面小组件）
```

- 适用于 Android 8.0 及以上（minSdk 26），竖屏，无广告、无第三方 SDK；
- 首次安装需在手机上允许「安装未知来源应用」；当前使用开发自签名证书，适合个人侧载；
- 原生外壳使用系统 WebView 加载同一份单文件页面，离线可用；
- 通知自动记账：监听微信支付/收款通知，在本机解析金额与商户（不联网、不上传），弹出确认卡，点「确认入账」才写入；
- 只需开启「通知使用权」；悬浮窗是**可选**的，未授权时自动降级为一条普通通知，点开进 App 确认页；
- 不申请无障碍、不录屏、不读屏幕；相册权限只服务于悬浮球小窗里的「识别截图」按钮，只有你主动点它时才读最新一张截图，OCR 全在本机完成；
- 识别结果按「通知 ID + 金额 + 商户摘要」10 分钟内去重，忽略确认卡不会产生任何账单；
- 在 App 内导出的 CSV / Excel / JSON 会保存到系统的「下载/辣脚记账」目录；
- APK 内的数据与浏览器/PWA 版**不互通**，换机前请用 JSON 备份迁移。

Android 壳工程与重新构建说明见 [android/README.md](android/README.md)。

### 方式 E：iPhone（PWA，推荐）

iPhone 不能安装 APK。最方便的做法是把 `dist/pwa/` 部署到任意 HTTPS 静态托管，
然后用 Safari 打开网址 →「分享」→「添加到主屏幕」。安装后是独立图标、全屏、可离线使用，
账单仍只存在本机。

- 可直接拖到 <https://app.netlify.com/drop> 上线，或上传到 GitHub Pages / Cloudflare Pages；
- 详细步骤、数据迁移与限制说明见 [docs/ios-install.md](docs/ios-install.md)。

## 三、整体架构

### 3.1 分层

```
┌─────────────────────────────────────────────┐
│  app.js  视图层                              │
│  页面渲染 / 事件委托 / 底部 Sheet / 弹窗       │
│  路由状态 state = { tab, route, cal, stats } │
└───────────────┬─────────────────────────────┘
                │ 只调用 QH.Store 的公开方法
┌───────────────▼─────────────────────────────┐
│  store.js  数据层                            │
│  transactions / budgets / settings / meta   │
│  localStorage 持久化 + 订阅通知               │
└───────────────┬─────────────────────────────┘
                │ 纯函数
┌───────────────▼─────────────────────────────┐
│  util.js 工具层   ·   charts.js 图表层        │
│  日期、金额、格式化    环形图、折线图（SVG）    │
└─────────────────────────────────────────────┘
```

- **单向数据流**：任何写操作都走 `Store.addTransaction / updateTransaction / setBudgets …`，
  写入后 `commit()` 落盘并 `notify()`；`app.js` 在启动时 `Store.subscribe(refresh)`，
  收到通知后按当前 `state` 重绘当前页面。记账、删除、改预算后所有数字立即刷新。
- **无框架**：使用经典 `<script>` 顺序加载，`file://` 双击可运行；模板字符串拼 HTML，
  事件统一委托到 `document`，避免几百个监听器。
- **视图状态与业务数据分离**：`state` 只保存当前 Tab、日历游标、统计维度、Sheet 表单，
  业务数据永远从 Store 读取，因此刷新页面不会丢状态（除临时表单）。
- **零依赖图表**：`charts.js` 直接输出 SVG 字符串，环形图用 `stroke-dasharray` 画弧，
  折线图用 polyline + 面积渐变，完全不引第三方图表库。

### 3.2 数据模型

存储键：`qinghe.ledger.v1`（另有 `qinghe.reminder.last` 记录当天提醒是否已触发）。

```json
{
  "version": 1,
  "transactions": [
    {
      "id": "t_xxx",
      "type": "expense",          // expense | income
      "amount": 32,
      "category": "lunch",        // breakfast/lunch/dinner/transport/...
      "note": "轻食沙拉",
      "date": "2026-10-19",
      "time": "11:43",
      "createdAt": "2026-10-19T03:43:00.000Z"
    }
  ],
  "budgets": {
    "monthly": 5000,
    "categories": { "breakfast": 300, "lunch": 700, "dinner": 800, "...": 0 }
  },
  "settings": {
    "currency": "¥",
    "theme": "matcha",            // matcha/ocean/tangerine/sakura/indigo
    "themeMode": "system",        // system | light | dark
    "reminders": {
      "summary": { "enabled": true, "time": "21:00" },
      "log":     { "enabled": false, "time": "20:00" }
    }
  },
  "meta": { "demo": false, "lastBackupAt": null }
}
```

- 读取时会经过 `normalize` / `migrate`，字段缺失、金额非法、日期格式错误都会被修正，
  因此旧备份或手工改坏的数据不会让页面白屏。
- 删除单条账单、清空示例、恢复备份都会同步更新 `meta.demo`，避免示例数据被误当成真实账单。

### 3.3 核心计算

| 能力 | 实现位置 | 说明 |
| --- | --- | --- |
| 日汇总 | `Store.daySummary` | 当日支出、收入、结余、笔数 |
| 月汇总 | `Store.monthSummary` | 当月支出、收入、笔数、日均 |
| 分类占比 | `Store.categoryBreakdown` | 按金额降序，用于环形图与图例 |
| 三餐占比 | `Store.mealBreakdown` | 早/午/晚各自金额、笔数、占餐饮比例 |
| 预算状态 | `Store.budgetStatus` | 剩余、是否超支、日均预算、今日可用 |
| 昨日对比 | `Store.daySummary` + `U.addDays` | 日总结页展示差额与百分比 |
| 统计区间 | `U.rangeFor(mode, anchor)` | 日/周/月/季/年统一成起止日期 |

预算口径：

- `日均预算 = 月度总预算 ÷ 当月天数`
- `今日可用 = 剩余预算 ÷ 剩余天数（含今天）`
- 当月支出 > 总预算时 `over=true`，首页预算卡、日总结、预算页统一变红提醒。

## 四、核心功能实现说明

### 4.1 三步记账（首页）

首页只保留两个大按钮：「记一笔」与「收入」，都集中在屏幕下半区，单手拇指可直接够到。

1. 点「记一笔」，底部弹出 3 列分类面板（早餐 / 午餐 / 晚餐 / 交通 / 购物 / 娱乐 / 日用 / 洗澡 / 饮水 / 住房 / 其他）；
2. 选中分类后进入金额 Sheet，输入金额，或点 ¥5 / ¥10 / ¥20 / ¥50 / ¥100；
3. 点「保存」。需要时可填备注。

- 三餐分类默认归类为 `breakfast / lunch / dinner`，自动带当天日期与当前时间。
- 点「收入」直接进入收入面板；金额 Sheet 顶部也可在「支出 / 收入」之间切换。
- 备注可选，最多 30 字；金额支持两位小数，非法输入会被拦截。
- 编辑账单复用同一个 Sheet，保存时走 `updateTransaction`，保留原 `id` 与创建时间。
- 快速金额是「填入」而不是「累加」，避免误触导致金额叠加。
- 首页不再平铺分类按钮，也不再显示今日账单，只留一条预算状态；账单查询统一放到日历。

### 4.2 日历账单

- `U.monthGrid(year, month)` 生成固定 42 格（6 行 × 7 列），周一开始，前后补邻月日期。
- 每格显示日期、当日总支出（紧凑格式，如 `1.6k`）、最多 3 个分类色点。
- 有支出的日期金额用主题色加粗；今天有浅色底；选中日期填充主题色。
- 支持月视图 / 周视图切换；左右滑动日历区域翻页（阈值 48px，且横向位移需大于纵向 1.4 倍，
  避免与页面上下滚动冲突）；翻月时保留原来的“日”，短月份自动收敛到月末。
- 点击任意日期后，日历下方直接展开完整日总结：当日总支出 / 总收入 / 结余、分类占比环形图与图例、当日账单列表；
  账单支持编辑、删除（二次确认）与补记。
- 日总结底部仍保留「详细分析」，可进入独立日详情页查看昨日对比、三餐专项统计。
- 日历页的「今天」按钮一键回到当前日期。

### 4.3 每日总结与提醒

- 每日总结已完整迁移到日历页：选中日期即在下方展示总收支、分类明细与账单列表，不再占用首页空间。
- 点日总结右上角「详细分析」进入日账单详情：
  - 分类占比环形图 + 图例（金额、百分比）；
  - 三餐单独统计（金额、笔数、占当日支出比例、进度条）；
  - 与昨日支出对比（多了/少了多少、百分比、昨日金额）；
  - 当日全部账单列表，可直接编辑/删除。
- 提醒：`checkReminders()` 每 30 秒检查一次；到达设定时间且当天未提醒过时，
  先尝试系统通知（需授权），再在应用内弹出小结弹窗；同一天只提醒一次。
- 提醒时间可分别设置「每日消费小结」与「每日记账提醒」。

### 4.4 统计分析

- 顶部切换日 / 周 / 月 / 季 / 年，左右箭头切换周期。
- 四张汇总卡：总支出、总收入、日均支出、三餐支出（含笔数、结余、占总支出的比例）。
- 分类支出占比环形图：按金额降序，展示全部 11 个支出分类，颜色与分类快捷按钮一致。
- 收支趋势折线图：支出、收入双系列，自动抽稀横轴标签，首系列带面积渐变。
- 「三餐专项统计」：周期内早/午/晚餐的金额、笔数、占总支出的比例、各自在三餐中的占比、
  每餐均价，以及三餐合计占周期总支出的比例。

### 4.5 预算管理

- 月度总预算 + 12 个分类预算（含三餐独立预算与洗澡/饮水/洗衣），保存后立即生效，每月 1 日按自然月重置额度。
- **本月可自由分配** 卡片固定在预算页顶部：
  `可自由分配 = 月度总预算 − 所有分类已分配预算之和`。
  修改总预算或任意分类预算时，输入事件会立即调用 `updateAllocCard()` 刷新，无需保存或刷新页面。
- 该数值是「预算分配余额」，只描述还有多少额度没有分配到分类，**不等于**当月消费剩余；
  预算页下方单独展示「本月消费剩余」，两者文案和计算完全分开。
- 已分配超过总预算时卡片变红、徽标改为「已超分配」，并提示差额。
- 首页预算条实时显示本月消费剩余、已用百分比、进度条；超支变红。
- 预算页展示：消费剩余、已花费/预算、日均预算、今日可用、本月剩余天数。
- 分类预算行显示「剩 ¥x / 超 ¥x / 已用 ¥x」，并配进度条；超支的分类进度条变红。
- 预算输入允许 0（表示不设预算），手机键盘为数字键盘。

### 4.6 新人引导

- 首次启动（`meta.onboarded !== true`）自动弹出 4 步引导：快速记账、日历查账、预算分配、数据归属。
- 每步只有一句说明和一张小示意图；底部「上一步 / 下一步」，末步按钮为「我知道了」。
- 点击「我知道了」「跳过」「以后再说」或遮罩关闭，都会调用 `Store.markOnboarded()` 写入本地，
  后续启动不再自动弹出；只有清除数据后才会重新出现。
- 「我的」→ 其他 →「新手使用教程」可随时重新打开完整引导，不改变已看过的标记。

### 4.7 数据、导出与设置

- **本地存储**：所有数据只写 `localStorage`，不上传任何服务器，无账号、无埋点。
- **CSV 导出**：UTF-8 BOM，Excel/WPS 直接打开不乱码；列为日期、时间、类型、分类、金额、备注。
- **Excel 导出**：生成 Excel 2003 XML（`.xls`），带表头、冻结首行、金额格式，零第三方库。
- **备份**：导出 JSON（含账单、预算、设置、元信息），恢复时校验 `transactions` 数组并迁移字段；
  恢复会整体替换当前数据，操作前有确认弹窗。
- **设置**：5 套低饱和主题（抹茶绿/海盐蓝/暖杏橙/樱花粉/远山紫）、深色模式（跟随系统/浅色/深色）、
  货币单位（最多 3 个字符，默认 ¥）、五类提醒（每日小结 / 每日记账 / 每周总结 / 每月总结 / 每年总结）。
- **PWA**：`manifest.webmanifest` 提供图标、竖屏、独立窗口、主题色和两个快捷方式
  （`?page=add` 直接弹出分类选择面板，`?tab=calendar` 直达日历）。

### 4.8 三餐 0 元与「未用餐」

- 早餐 / 午餐 / 晚餐的金额 Sheet 里有「这餐没吃 / 记 0 元」开关；开启后金额自动归零，保存为
  `amount: 0, uneaten: true`，并在列表中弱化显示为「未用餐」。
- 0 元三餐只允许三餐支出；交通、购物等其他分类输入 0 仍会被拦截，避免产生无意义账单。
- 统计口径：**计入账单笔数，不计入支出总额**；预算扣减、日均支出、分类占比都不包含 0 元记录。
- 编辑一条 0 元记录并填入金额后，会自动清除 `uneaten`，恢复为普通支出。

### 4.9 通知自动记账（Android，通知监听 + 确认卡）

- 入口：「我的」→「通知自动记账」。网页 / PWA 读不到系统通知，会提示安装 Android 版。
- 首次使用：① 系统设置 → 通知使用权 → 允许辣脚记账；②（可选）允许悬浮窗；③ 关闭电池限制，
  小米 / HyperOS 建议同时允许「自启动」。
- 触发方式：无需任何手动操作。微信支付成功后系统弹出「微信支付」通知，App 监听到该通知后
  在本机解析金额、商户与时间（纯本地正则，不联网、不上传）。
- 结果处理：悬浮窗已授权 → 直接弹确认卡；未授权 → 发一条普通通知「识别到一笔微信支付 ¥x」，
  点开进 App 确认页。两种情况都必须点「确认入账」才写入，忽略不产生账单。
- **不使用无障碍、不截图、不录屏、不读相册**：v1.5.0 已删除磁贴、截图 OCR、Tesseract 模型
  与全部相关代码；只读取包名 `com.tencent.mm` 的通知文本。
- 去重：以「通知 ID + 金额 + 商户摘要」为键，10 分钟内同一条交易只处理一次。
- 日志：`adb logcat -s QHNotify` 可看到每条微信通知的原始标题/正文、匹配结果与状态。
- 已知边界：微信内关闭通知、通知被折叠或微信改版文案时可能识别不到；可手动记账或使用
  「导入微信 / 支付宝账单」。

### 4.10 微信 / 支付宝账单导入

- 入口：「我的」→「导入微信 / 支付宝账单」。支持 CSV（UTF-8 / GB18030 自动识别）、XLSX、
  Excel 2003 XML（`.xls`）；PDF 需要 OCR，当前版本会提示改用 CSV/XLSX。
- 解析全部在浏览器 / WebView 本地完成：自写 ZIP 目录读取 + `DecompressionStream('deflate-raw')`
  解开 XLSX，不依赖第三方库，不上传文件。
- 兼容微信、支付宝常见表头：交易时间、交易类型、交易对方、商品、金额、收/支、交易状态、分类；
  分类关键词覆盖三餐、洗澡、饮水、交通、购物、娱乐、日用、住房等，未命中归「其他」。
- 导入前显示预览：逐行勾选、修改分类、标记「已存在，将跳过」；确认后调用
  `Store.addTransactions` 批量写入，批内和库内都按指纹去重，并返回新增 / 跳过数量。

### 4.11 预算校准与累计结余

- **校准本月已消费**：预算页「校准本月已消费」可填入一个与实际账单不同、但符合真实开销的数值。
  它只影响预算剩余与累计结余，不修改任何账单明细；可随时「恢复自动统计」。
- **累计结余**：统计页顶部卡片。单月结余 = 当月总预算 − 当月实际支出；累计结余 = 历史月份结余之和。
  同时展示近 12 个月结余柱状图（绿=结余，红=超支）。没有账单、没有校准、没有历史预算快照的月份
  记 0，避免把当前预算错误套用到所有空月份。

### 4.12 自定义周期与周期推送

- 日历页顶部「自定义周期统计」：选择起止日期，生成该时间段总支出 / 总收入 / 结余 / 笔数、
  分类占比明细，并可导出这段时间的 CSV。
- 提醒设置新增每周 / 每月 / 每年总结，独立开关与时间；触发时展示周期总支出、Top3 分类、结余，
  有系统通知权限时同时发通知。周总结在周一触发，月总结在每月 1 日，年总结在 1 月 1 日。
- Android 端由原生 `notify()` 桥发系统通知（WebView 内没有 Web Notification）；权限状态会显示在
  「我的 → 提醒」底部，点击「去开启」可再次申请或跳到系统设置。
- 通知权限检测入口会打开系统通知设置（Android）或浏览器站点设置（Web）；iOS PWA 关闭后无法
  运行后台定时器，这是系统限制，应用会在下次打开时补检查。

## 六、使用说明（功能操作指引）

### 记一笔

1. 首页点「记一笔」，在弹出面板中选择早餐、午餐、晚餐或其它分类；
2. 输入金额，或点 5 / 10 / 20 / 50 / 100；
3. 需要的话填备注，点「保存」。保存后预算条与日历数据立即更新。

> 记收入：直接点首页「收入」，或在记账面板顶部切到「收入」。

### 查看 / 修改 / 删除账单

- 进入日历，点任意日期，下方日总结的账单列表右侧有铅笔/垃圾桶图标；
- 点账单行任意位置也可打开编辑面板；
- 删除会弹出确认框，确认后不可撤销。

### 日历

- 「月 / 周」切换视图；点左右箭头或直接左右滑动日历翻页；
- 点日期查看当天明细；点「今天」回到当前日期；
- 日期下方的彩色圆点代表当天出现的支出分类。

### 看总结

- 日历页点任意日期，下方即展示该日总收支、分类占比和全部账单；
- 点日总结右上角「详细分析」进入日详情，可看三餐统计与昨日对比。

### 新人教程

- 首次启动会自动弹出 4 步引导，点「我知道了」后不再出现；
- 想再看：「我的」→ 其他 →「新手使用教程」。

### 统计

- 底部「统计」→ 选日/周/月/季/年 → 左右箭头切换周期；
- 环形图看分类占比，折线图看收支趋势，底部看三餐专项。

### 预算

- 首页预算条 →「预算管理」，或「我的」→ 预算管理；
- 顶部「本月可自由分配」会随着你输入总预算和分类预算实时变化；
- 它表示还没分配出去的预算，不等于本月消费剩余；
- 填完点「保存预算」，超支后首页和预算页会出现红色提醒。

### 提醒

- 「我的」→ 打开「每日消费小结」或「每日记账提醒」开关，设置时间；
- 首次开启会请求系统通知权限（Android 13+ 首次启动也会自动请求一次）；未授权时仍会在应用内弹窗提醒；
- 提醒需要页面处于打开状态（可后台），浏览器无法在完全关闭后唤醒网页。

### 导出 / 备份 / 恢复

- 「我的」→ 数据管理：
  - 导出 CSV / 导出 Excel：直接下载到本地；
  - 备份数据：下载 JSON；
  - 恢复备份：选择之前导出的 JSON，确认后覆盖当前数据。

### 主题 / 深色 / 货币

- 「我的」→ 外观：点色块切换主题；选「跟随系统 / 浅色 / 深色」；
- 货币单位可改为 `$`、`€`、`元` 等最多 3 个字符，所有金额前缀即时更新。

## 八、隐私与边界

- **纯本地**：没有后端、没有账号、没有网络请求（除加载自身静态资源），不会上传任何账单。
- **数据位置**：浏览器 `localStorage`。清理浏览器数据、卸载浏览器、换设备都会导致数据丢失，
  请定期用「备份数据」导出 JSON。
- **单文件版**：数据绑定到该文件的本地存储域；换一个路径/文件名可能读不到旧数据，
  建议固定存放位置，或使用 JSON 备份迁移。
- **提醒限制**：网页无法在完全关闭后定时唤醒；系统通知还受浏览器权限、iOS 版本、
  是否安装到主屏幕影响。站内弹窗提醒始终可用。Android 原生版在应用进程存活时按设定时间检查；
  系统省电策略可能延迟后台任务，建议在权限引导中关闭电池限制。
- **通知自动记账限制**：仅 Android 版可用，需要开启「通知使用权」（设置 → 通知使用权 → 辣脚记账）；
  App 只读取微信（`com.tencent.mm`）的通知文本，在本机正则解析金额与商户，不读屏幕、不截图、
  不录屏、不读相册、不联网；识别后必须点「确认入账」才写入，忽略不产生账单。
  微信未弹通知（如应用内关闭通知）、通知被折叠或文案改版时可能识别不到，可手动记账或账单导入。
- **悬浮窗可选**：未授予悬浮窗时，识别结果降级为一条普通通知，点开进 App 确认，不会拦截流程。
- **导入限制**：PDF 账单暂不支持（需要本地 OCR 引擎）；请从微信 / 支付宝导出 CSV 或 XLSX。
- **性能边界**：所有统计在内存中完成，适合个人数年量级账单；若单次导入数万行，预览会分批渲染。
- **PWA 安装**：iOS 需 Safari「添加到主屏幕」；Android Chrome 支持安装提示；
  Service Worker 仅在 `https` 或 `localhost` 下注册。
- **Excel 格式**：导出的是 Excel 2003 XML（`.xls`），Excel、WPS、Numbers 均可打开；
  如只需通用格式，请选 CSV。
